# Capture Work

### 업무를 수행하는 순간 그 과정을 실행 가능한 표준업무로 변환하는 프로세스 캡처 도구

업무의 병목은 사용자의 판단이 아니라, 여러 시스템 사이에서 경로를 다시 찾고 같은 입력을 반복하며 화면을 오가는 시간에 있습니다.

`Capture Work`는 사용자가 실제 업무를 한 번 수행하면 그 과정을 클릭 로그가 아니라 업무 단위의 단계, 주의사항, 완료 조건, 예외 상황으로 구조화합니다. 이후 같은 업무가 필요할 때는 긴 영상 대신 실제 화면 위에서 다시 따라갈 수 있는 가이드로 재생합니다.

[실행 화면](https://celeste0423.github.io/tutorial_making_program_demo/) · [저장소](https://github.com/celeste0423/tutorial_making_program_demo)

## 전산 업무의 병목은 경로를 다시 찾는 시간입니다

회사 안에 Excel, ERP, 메일, 파일 탐색기 같은 도구가 늘어날수록 간단한 업무 하나를 끝내기 위해 거쳐야 할 화면도 늘어납니다. 사용자는 입력값 자체보다 어떤 화면에서 어떤 버튼을 눌러야 하는지 기억하는 데 더 많은 시간을 씁니다.

이 문제는 신규 입사자만의 문제가 아닙니다. 숙련자도 자주 쓰지 않는 업무를 다시 처리할 때는 동일한 탐색을 반복합니다. 업무 매뉴얼이 있어도 실제 화면과 버튼 위치는 계속 달라지고, 영상 매뉴얼은 필요한 장면을 다시 찾기가 어렵습니다.

`Capture Work`는 이 병목을 다음 방식으로 바꿉니다.

```text
한 번의 실제 업무 수행
         ↓
앱 전환, 클릭, 첨부, 제출, 판단 지점 기록
         ↓
업무 카드 5~10개로 자동 구조화
         ↓
초보자 화면 위에서 다시 따라 할 수 있는 가이드 생성
```

## 업무를 영상이 아니라 실행 가능한 단계로 남깁니다

이 프로젝트는 화면 녹화 툴이 아닙니다. 사용자가 실제 업무를 마친 뒤, 시스템은 다음 정보를 하나의 업무 흐름으로 정리합니다.

- 어떤 앱을 어떤 순서로 열었는가
- 어떤 버튼과 입력 영역을 눌렀는가
- 어디서 복사와 붙여넣기가 일어났는가
- 어떤 단계에서 첨부와 저장, 제출이 발생했는가
- 어디에서 사용자의 판단이나 주의가 필요했는가
- 업무가 완료되었다고 볼 수 있는 조건은 무엇인가

그 결과 사용자는 긴 타임라인 대신 단계별 업무 카드를 보게 됩니다. 카드는 순서를 옮기고, 두 단계를 합치고, 이름과 주의사항을 수정할 수 있습니다.

## 구매 요청 업무를 다음 장면으로 보여줍니다

현재 공개된 실행 화면은 구매 요청 시나리오를 기준으로 구성되어 있습니다.

1. Excel에서 승인 완료된 구매 대상을 확인합니다.
2. ERP에서 구매 요청 화면을 열고 품목번호와 수량을 입력합니다.
3. 파일 탐색기에서 최근 견적서를 첨부합니다.
4. 메일에서 생성된 구매번호를 담당자에게 전달합니다.
5. 시스템은 위 과정을 업무 카드와 주의사항으로 정리합니다.
6. 이후 초보자 화면 위에서 실제 클릭 위치를 다시 강조하며 재생합니다.

이 흐름은 단순한 녹화가 아니라 `업무 수행 → 구조화 → 재생`의 전체 경험을 한 번에 보여주기 위한 최소 시나리오입니다.

## 사용자는 타임라인이 아니라 업무 카드를 편집합니다

영상 편집기처럼 길게 늘어선 타임라인은 다시 복잡해집니다. `Capture Work`는 업무 단위 카드 편집을 기본 작업 방식으로 둡니다.

예를 들어 구매 요청 업무는 다음처럼 정리됩니다.

```text
[1. 구매 대상 확인]     Excel
승인 상태인 품목을 선택합니다.
완료 조건: 승인 여부 확인

[2. 구매 요청 등록]     ERP
품목번호와 수량을 입력합니다.
주의: VAT 포함 여부 확인

[3. 견적서 첨부]        파일 탐색기
최근 30일 이내 견적서를 첨부합니다.

[4. 담당자 통보]        메일
생성된 구매번호를 전달합니다.
```

사용자는 카드 순서를 옮기고, 두 카드를 합치고, 필요하면 조건을 추가합니다. 목표는 복잡한 편집기가 아니라 PowerPoint를 수정할 수 있는 사용자가 다룰 수 있는 수준의 업무 편집 경험입니다.

## 직접 체험하기

[실행 화면](https://celeste0423.github.io/tutorial_making_program_demo/) 에서 다음 흐름을 따라가면 됩니다.

1. 첫 화면에서 제품 설명과 구매 요청 흐름을 확인합니다.
2. 재생 영역에서 업무 단계가 앱별로 어떻게 전환되는지 봅니다.
3. 오른쪽 가이드 패널에서 단계 설명, 주의사항, 자동 감지 신호를 확인합니다.
4. 하단 카드 영역에서 단계별 업무 구성이 어떻게 정리되는지 확인합니다.
5. 포함된 재생 영상을 통해 캡처에서 가이드 생성까지의 짧은 흐름을 한 번 더 볼 수 있습니다.

전체 흐름은 약 15초 내외의 요약 재생과 카드형 업무 화면으로 구성되어 있습니다.

## 현재 범위와 확장 방향

현재 공개 버전은 다음 범위를 중심으로 구현했습니다.

적용 대상 | 현재 상태 | 보여주는 내용
--- | --- | ---
웹 소개 페이지 | 구현 완료 | 제품 정의, 카드형 업무 흐름, 재생 화면
작동 시나리오 | 구현 완료 | 구매 요청 업무의 캡처와 재생 흐름
데스크톱 캡처 엔진 | 설계 범위 | 활성 프로그램, 창 제목, UI 요소, 첨부와 제출 감지
라이브 오버레이 플레이어 | 설계 범위 | 실제 버튼 강조와 초보자용 따라 하기 모드

화면을 읽는 기술은 플랫폼마다 다를 수 있지만 결과는 같은 형식으로 저장할 수 있습니다. 업무 이름, 단계, 주의사항, 완료 조건, 반복 구간, 앱 전환 흐름이 동일한 구조로 쌓이면 웹이든 데스크톱이든 같은 방식으로 재생할 수 있습니다.

## 저장소 구성

경로 | 내용
--- | ---
`index.html` | 소개 페이지 구조와 전체 실행 화면
`styles.css` | 비주얼 시스템과 카드형 레이아웃
`script.js` | 단계 재생, 가이드 패널, 카드 선택 로직
`assets/demo-reel.webm` | 캡처에서 재생까지 이어지는 짧은 재생 영상
`.github/workflows/deploy.yml` | GitHub Pages 자동 배포 워크플로

## 로컬에서 확인하기

정적 사이트라서 `index.html`을 브라우저에서 바로 열어도 확인할 수 있습니다. 간단한 로컬 서버로 확인하려면 현재 디렉터리에서 다음 명령을 실행하면 됩니다.

```bash
python -m http.server 4173
```

브라우저에서 `http://127.0.0.1:4173`을 열면 됩니다.

## 배포 방식

이 저장소는 GitHub Pages를 `GitHub Actions` 방식으로 배포합니다.

1. `main` 브랜치에 변경사항을 푸시합니다.
2. `.github/workflows/deploy.yml`이 자동으로 실행됩니다.
3. 정적 파일이 GitHub Pages로 배포됩니다.
4. 공개 주소는 `https://celeste0423.github.io/tutorial_making_program_demo/`입니다.

페이지가 바로 보이지 않으면 `Actions` 탭에서 `Deploy to GitHub Pages` 워크플로 상태를 확인하면 됩니다. Pages를 처음 켠 직후에는 잠시 `404`가 반환될 수 있으며, 배포가 끝나면 정상적으로 열립니다.
